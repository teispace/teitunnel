Teitunnel runs on **macOS 14 or later**, **Windows 10 and 11** and **Linux** (GNOME, KDE and
other desktops), and as a command line and Docker image on servers. It's free, and it
installs and checks **cloudflared** for you.

## Download

The button below picks the right file for your computer. Other systems are in the tabs
further down, and every file is also on the [download page](/download/).

## Install it

<Tabs items={["macOS", "Windows", "Linux", "Server (CLI)", "Docker"]}>
  <Tab value="macOS">
    <Downloads os="macos" />

    <Steps>
      <Step>
        <h3>Open the disk image</h3>

        Open **Teitunnel_…_universal.dmg** from your Downloads folder. One download runs on
        both Apple silicon and Intel Macs.
      </Step>
      <Step>
        <h3>Drag Teitunnel to Applications</h3>

        Drag the Teitunnel icon onto the **Applications** folder in the window that opens, then
        eject the disk image.
      </Step>
      <Step>
        <h3>Open it</h3>

        Open Teitunnel from Applications or Spotlight. The first time, macOS asks whether to
        open an app downloaded from the internet: choose **Open**.
      </Step>
    </Steps>

    Teitunnel lives in the menu bar as well as the Dock, and keeps credentials in your
    keychain.

    Prefer Homebrew? The same signed app, with `teitunnel-cli` on your `PATH`:

    ```sh
    brew install --cask teispace/tap/teitunnel
    ```
  </Tab>
  <Tab value="Windows">
    <Downloads os="windows" />

    Choose **x64** for most PCs, or **Arm64** for Windows on Arm (Surface Pro X, Snapdragon
    laptops). Not sure? **Settings ▸ System ▸ About ▸ System type** says which.

    <Steps>
      <Step>
        <h3>Run the installer</h3>

        Open **Teitunnel_…-setup.exe** from your Downloads folder.
      </Step>
      <Step>
        <h3>Let Windows run it</h3>

        The first time, Microsoft Defender SmartScreen may say *Windows protected your PC*.
        Choose **More info**, then **Run anyway**.
      </Step>
      <Step>
        <h3>Finish</h3>

        It installs for your user, without an administrator, and opens. Find it later in the
        Start menu. Its icon sits in the notification area next to the clock.
      </Step>
    </Steps>

    Credentials are kept in Windows Credential Manager, and routes can keep running with Task
    Scheduler.
  </Tab>
  <Tab value="Linux">
    The easiest way is Teitunnel's package repository: your system then installs updates
    with everything else. Packages and the repository are signed with
    [Teitunnel's key](/linux/teitunnel.asc).

    ```sh
    # Ubuntu, Debian, Linux Mint, Pop!_OS
    curl -fsSL https://teitunnel.teispace.com/linux/teitunnel.asc \
      | sudo gpg --dearmor -o /usr/share/keyrings/teitunnel.gpg
    echo "deb [signed-by=/usr/share/keyrings/teitunnel.gpg] https://teitunnel.teispace.com/linux/deb stable main" \
      | sudo tee /etc/apt/sources.list.d/teitunnel.list
    sudo apt update && sudo apt install teitunnel

    # Fedora, RHEL, Rocky, AlmaLinux
    sudo curl -fsSLo /etc/yum.repos.d/teitunnel.repo https://teitunnel.teispace.com/linux/teitunnel.repo
    sudo dnf install teitunnel

    # openSUSE
    sudo zypper addrepo https://teitunnel.teispace.com/linux/teitunnel.repo
    sudo zypper install teitunnel
    ```

    Or download a package:

    <Downloads os="linux" />

    Pick the package for your distribution:

    ```sh
    # Ubuntu, Debian, Linux Mint, Pop!_OS
    sudo apt install ./Teitunnel_*_amd64.deb

    # Fedora, RHEL, openSUSE (zypper install on openSUSE)
    sudo dnf install ./Teitunnel-*.x86_64.rpm

    # Anything else: the AppImage
    chmod +x Teitunnel_*.AppImage
    ./Teitunnel_*.AppImage
    ```

    Installing the `.deb` with `apt` (not `dpkg -i`) also installs what it needs. On an Arm64
    machine, use the `arm64` / `aarch64` files instead.

    It needs **WebKitGTK 4.1**: Ubuntu 22.04, Debian 12, Fedora 40 or later. The AppImage
    also needs FUSE 2 (`sudo apt install libfuse2`, or `libfuse2t64` on Ubuntu 24.04).
    Credentials are kept by the Secret Service (GNOME Keyring or KWallet), which must be
    installed and unlocked; routes can keep running as a `systemd --user` service.
  </Tab>
  <Tab value="Server (CLI)">
    `teitunnel-cli` is released on its own for servers without a desktop:

    <Downloads cli />

    On Linux:

    ```sh
    curl -LO https://github.com/teispace/teitunnel/releases/latest/download/teitunnel-cli_<version>_linux-x64.tar.gz
    sudo tar -xzf teitunnel-cli_*_linux-x64.tar.gz -C /usr/local/bin teitunnel-cli
    teitunnel-cli --version
    ```

    With Homebrew, on macOS or Linux (it installs `cloudflared` too, and shell completions):

    ```sh
    brew install teispace/tap/teitunnel-cli
    ```

    Then follow [Servers and containers](/docs/guides/servers). If you have the desktop app,
    **Settings ▸ General ▸ Command line ▸ Install** puts the same CLI on your `PATH`.
  </Tab>
  <Tab value="Docker">
    The image has the command line and Cloudflare's own `cloudflared`, runs as a non-root user
    and keeps its state in `/data`:

    ```sh
    docker run -d --name teitunnel --restart unless-stopped \
      -e CLOUDFLARE_API_TOKEN -v teitunnel:/data ghcr.io/teispace/teitunnel
    ```

    It's built for `linux/amd64` and `linux/arm64` from each release's own `teitunnel-cli`,
    and tagged with the version (`0.1.0`), the minor version (`0.1`) and `latest`. To check
    that an image came from this repository's release workflow:

    ```sh
    gh attestation verify oci://ghcr.io/teispace/teitunnel:latest --repo teispace/teitunnel
    ```

    See [Docker Compose stacks](/docs/tutorials/docker-compose) and
    [Servers and containers](/docs/guides/servers#docker).
  </Tab>
</Tabs>

## The first launch

Teitunnel opens on **Overview**. Before anything can be shared it needs **cloudflared**,
Cloudflare's connector:

- If you already have one (from Homebrew, winget or your package manager), Teitunnel finds and
  uses it.
- If not, choose **Install cloudflared**. Teitunnel downloads the latest release from GitHub
  and checks it before use: the download must match the digest GitHub publishes, the binary
  must match the checksum in Cloudflare's release notes, and on macOS its code signature must
  be Cloudflare's.

The managed copy lives in Teitunnel's own folder and is updated from
**Settings ▸ cloudflared**. When it updates, running connectors move to the new version
without dropping your routes.

## Updates

Teitunnel checks for a new version when it opens and once a day, and downloads it in the
background. Every update is signed, and the app refuses one whose signature doesn't match
the key built into it. When an update is ready, the sidebar says so: choose
**Restart to Update**, or just quit, and it installs. On Linux, `.deb` and `.rpm`
installs wait for **Restart to Update**, because your system asks for an administrator
password. If you installed from Teitunnel's repository, `sudo apt upgrade` or
`sudo dnf upgrade` brings new versions too.

A check downloads one small file from GitHub and sends nothing about you. To check only
when you ask, turn off **Settings ▸ General ▸ Check for updates automatically**; on macOS,
**Teitunnel ▸ Check for Updates…** checks now.

## Uninstall

Uninstalling doesn't change your Cloudflare account: tunnels, routes and DNS records stay.
To clean up, first remove your routes in Teitunnel and turn off **Keep running when Teitunnel
quits** in **Tunnels**, then **Settings ▸ Accounts ▸ Disconnect** deletes the credentials
from your keychain.

| System | Remove the app | Settings and history |
|---|---|---|
| macOS | Drag Teitunnel from Applications to the Trash | `~/Library/Application Support/com.teispace.teitunnel` |
| Windows | **Settings ▸ Apps ▸ Installed apps ▸ Teitunnel ▸ Uninstall** | `%APPDATA%\com.teispace.teitunnel` |
| Linux | `sudo apt remove teitunnel`, `sudo dnf remove teitunnel`, or delete the AppImage; to drop the repository too, delete `/etc/apt/sources.list.d/teitunnel.list` or `/etc/yum.repos.d/teitunnel.repo` | `~/.local/share/com.teispace.teitunnel` |

Delete that folder too if you want nothing left behind. To build Teitunnel yourself instead,
see the [contributing guide](https://github.com/teispace/teitunnel/blob/main/CONTRIBUTING.md).
