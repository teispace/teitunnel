---
title: SSH, RDP and databases through Cloudflare Tunnel
description: Reach a machine's SSH, Remote Desktop or database from anywhere through Cloudflare Tunnel, with no inbound port open, and lock it down with Cloudflare Access.
---

A route doesn't have to be a website. It can carry SSH, Remote Desktop, or any TCP service
such as Postgres, so you can reach a machine at home or in the office without opening port 22
to the internet.

## 1. Add the route

On the machine you want to reach, add a route with a non-HTTP origin:

```sh
teitunnel route add ssh.example.com ssh://localhost:22 --allow you@example.com
teitunnel route add desktop.example.com rdp://localhost:3389 --allow you@example.com
teitunnel route add db.example.com tcp://localhost:5432 --allow you@example.com
```

In the app: **New Route**, service `ssh://localhost:22`, and under **Advanced** turn on
**Require a login**. The `--allow` / login part is optional but strongly recommended: without
it, anyone with cloudflared can reach the port (SSH still asks for your key or password).

<Callout>
Keep the machine's routes running with **Keep running when Teitunnel quits**
(`always-on on`), or you won't be able to reach it after a restart.
</Callout>

## 2. Connect from your computer

A browser can't open these routes. On the computer you connect *from*, install
[cloudflared](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/)
(`brew install cloudflared`, `winget install Cloudflare.cloudflared`, or your package
manager). The route's details in Teitunnel show the exact commands for it.

<Tabs items={["SSH", "Remote Desktop", "Database or TCP"]}>
  <Tab value="SSH">
    Once:

    ```sh
    ssh -o ProxyCommand="cloudflared access ssh --hostname %h" you@ssh.example.com
    ```

    To make plain `ssh ssh.example.com` work, add this to `~/.ssh/config`:

    ```
    Host ssh.example.com
      ProxyCommand cloudflared access ssh --hostname %h
    ```

    With a login on the route, cloudflared opens your browser to sign in the first time and
    remembers it for the session.
  </Tab>
  <Tab value="Remote Desktop">
    Start a local listener, then point your Remote Desktop client at it:

    ```sh
    cloudflared access rdp --hostname desktop.example.com --url rdp://localhost:3389
    ```

    Connect to `localhost:3389` in Microsoft Remote Desktop (Windows App on macOS).
  </Tab>
  <Tab value="Database or TCP">
    ```sh
    cloudflared access tcp --hostname db.example.com --url localhost:5432
    ```

    Then connect your client to `localhost:5432` as if the database were local
    (`psql -h localhost -p 5432 …`). Use another local port if 5432 is taken on your side.
  </Tab>
</Tabs>

## Many machines, or a whole network

One route per service is right for a few machines. To reach many hosts and ports (every
server in a rack, a NAS, printers), share a [private network](/docs/guides/private-networks)
and connect with the Cloudflare WARP client instead: then `ssh 192.168.1.20` just works.
