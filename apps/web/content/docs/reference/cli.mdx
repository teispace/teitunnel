`teitunnel` works with the accounts you connected in the app. Every change goes
through the same preview as the app: you see the plan before anything changes.

## Install it

The app puts the `teitunnel` command on your PATH:

- **Windows:** the installer does it (a copy in your user's `WindowsApps` folder, which is
  already on the PATH), and uninstalling removes it.
- **Linux:** the `.deb` and `.rpm` install `/usr/bin/teitunnel`. With the AppImage,
  Teitunnel offers once, after setup, to put it in `~/.local/bin`.
- **macOS:** Teitunnel offers once, after setup, to link it into Homebrew's `bin` (or
  `/usr/local/bin`; if it can't write there, it shows the one `sudo ln -s …` command to
  run). Installed with Homebrew (`brew install --cask teispace/tap/teitunnel`), it's linked
  for you.

You can add or remove it any time in **Settings ▸ General ▸ Command line**. It updates with
the app. For servers without the app, download it on its own from the
[download page](/download/#cli).

The first time it reads your Cloudflare token, macOS asks whether `teitunnel` may use
the keychain item Teitunnel created. Choose **Always Allow** to not be asked again.

## Where routes run

Routes are served by the app while it's open, all the time with
[Always-on](/docs/concepts/run-modes) (`teitunnel always-on on`), or by `teitunnel up` on a
server or in a container. Without the app, give the API token in `CLOUDFLARE_API_TOKEN` or
`CLOUDFLARE_API_TOKEN_FILE`; it's never stored
([Servers and containers](/docs/guides/servers)).

## With the app running

When the Teitunnel app is running, `teitunnel` uses it through its
[control connection](/docs/guides/integrations/):

- `teitunnel share 3000` asks the app to share the port. The share shows up in the app's
  Quick Share and keeps running after the command ends; stop it there or with
  `teitunnel shares --stop <url>`. The first time, the app asks you to allow the command
  line (choose **Always Allow** to not be asked again). `--for` still works, and `--here`
  shares from the terminal instead.
- `teitunnel shares` lists the app's shares too, and `--stop` stops any of them.
- `teitunnel routes` shows the status the app's connectors report.
- `teitunnel status` says whether the app runs, its tunnels and what it shares.

Without the app every command works on its own.

## Sharing from the terminal

Without the app (or with `--here`), `share` runs a Quick Share for exactly as long as the
command. Ctrl-C, closing the terminal or `--for` stops it. The URL is the only line on
standard output, so `URL=$(teitunnel share 3000 | head -1)` works in scripts. `share`
doesn't need an account, only cloudflared (the app's copy, or one on your system). Once the
URL is live, `share` checks it through Cloudflare and, if your dev server refuses the
address or the service streams events a Quick Share can't carry, says what to do on
standard error; it keeps sharing either way. `share --on` runs the tunnel's connector itself
when neither the app nor an Always-on service does (a server, a CI job; see
[Previews in CI](/docs/guides/ci-previews)).

Shares go through the [inspector](/docs/guides/inspector) unless you pass `--no-inspect`:
each request is printed on standard error (`--quiet` stops that) and kept for
`teitunnel traffic`. `teitunnel traffic` reads the inspector's history in the app's
database, written by the app and by every `teitunnel` command with an inspector, with
credentials masked; so `traffic get --reveal` can't show them, and a replay from history
leaves masked headers out (set them again with `--set-header`).

Before `share` and `route add` make a service public, the
[exposure check](/docs/guides/exposure-check/) looks at it for leaks (a `.env` file, the git
folder, debug pages…) and prints what it finds on standard error; `--strict` makes that an
error (exit status 1) instead of a warning.

## Exit status

0 when it worked, 1 when it didn't, 2 for a mistyped command, and 3 when a hostname is held
by someone else (a share never takes one; other commands need `--take-over`).

## Options many commands share

| Option | Meaning |
|---|---|
| `-a, --account <ACCOUNT>` | Which account, when several are connected (its name or id). |
| `-y, --yes` | Apply without asking (needed when there's no terminal to ask on, e.g. in scripts). |
| `--replace` | Also allow what needs a confirmation: replacing or deleting DNS records Teitunnel didn't create, or routing a public range ([Private networks](/docs/guides/private-networks)). |
| `--take-over` | Take a hostname someone else holds (their reservation, or another machine's route) ([Teams](/docs/guides/ci-previews#teams-sharing-one-account)). Without it, the command exits with status 3. |
| `--tunnel <TUNNEL>` | Which of this machine's tunnels a change or export is about ([Several tunnels](/docs/guides/several-tunnels)). Default: the tunnel carrying the route, or the default tunnel. |
| `--json` | Machine-readable output, for scripts. |
| `--app`, `--here` | Go through the running app (and fail if it isn't running), or don't use the app even when it runs. |

## setup

Connect a Cloudflare account with an API token (stored in the OS keychain).

On a server or in a container without a keychain, don't store it: set `CLOUDFLARE_API_TOKEN` (or `CLOUDFLARE_API_TOKEN_FILE`) for each command instead. The token needs Cloudflare Tunnel, DNS and Zone permissions; create one from the template at https://dash.cloudflare.com/profile/api-tokens.

```sh
teitunnel setup
```

Examples:

```sh
teitunnel setup  # store an API token in the keychain
```

See [Accounts and permissions](/docs/guides/accounts/) and [Permissions and scopes](/docs/reference/permissions/) for what the token needs, and [Servers and containers](/docs/guides/servers/) for giving it in the environment.

## up

Run this machine's tunnels in the foreground until stopped (servers, containers).

In a folder with a teitunnel.yml, its plan is shown and applied first, and its shares run as long as this does.

```sh
teitunnel up [OPTIONS]
```

| Option | Description |
|---|---|
| `-f, --file <PATH>` | The project file to apply first (default: teitunnel.yml in this folder or the nearest one above it in the repository, when there is one). |
| `--no-project` | Don't apply a project file, even if there is one here. |
| `-a, --account <ACCOUNT>` | Account name or id (default: the file's `account`). |
| `-y, --yes` | Apply without asking. |
| `--replace` | Also allow what needs a confirmation (replacing DNS records Teitunnel didn't create). |
| `--strict` | Don't start a share when the exposure check finds a leak. |

Examples:

```sh
teitunnel up               # run this machine's tunnels (servers, Docker)
teitunnel up --no-project  # ignore the teitunnel.yml in this folder
```

See [Servers and containers](/docs/guides/servers/) and [Project files](/docs/guides/project-file/).

### local-domain add

Give a local service an HTTPS address like https://shop.test.

Names end in .localhost (works in browsers with no setup), .test (every tool, after a one-time resolver entry) or .local (also phones on your network). Served by the Teitunnel app when it runs, otherwise from this terminal until Ctrl-C.

```sh
teitunnel local-domain add [OPTIONS] <NAME> <TARGET>
```

| Argument | Description |
|---|---|
| `<NAME>` | The name, e.g. shop.test (".localhost" is added when there's no suffix). |
| `<TARGET>` | The service: a port (3000), host:port, or a URL (https://localhost:5173). |

| Option | Description |
|---|---|
| `--wildcard` | Subdomains (*.name) go to the same service. |
| `--no-https` | Plain HTTP only (no certificate). |
| `--inspect` | Record its requests (see `teitunnel traffic`). |
| `--no-serve` | Only save it; don't serve it from this terminal when the app isn't running. |
| `--here` | Serve it from this terminal even if the app runs. |

Examples:

```sh
teitunnel local-domain add shop.test 3000  # https://shop.test on this computer
```

## serve

Run this machine's tunnels plus a web dashboard and JSON API (servers).

Listens on 127.0.0.1:8765 unless told otherwise. Sign in with the password set by `--set-password` (or TEITUNNEL_WEB_PASSWORD); automation uses API keys.

```sh
teitunnel serve [OPTIONS]
```

| Option | Description |
|---|---|
| `--listen <LISTEN>` | Where to listen. Default: `127.0.0.1:8765`. |
| `--allow-remote` | Allow listening on a non-loopback address (put TLS in front of it). |
| `--secure-cookies` | Mark the session cookie Secure (when served over HTTPS). |
| `--set-password` | Set the dashboard password (read from the terminal) and exit. |
| `--no-mcp` | Don't serve the MCP endpoint (`/mcp`, for AI agents with an API key). |
| `--mcp-mode <MCP_MODE>` | The MCP endpoint's mode: read-only, ask (default) or full. |
| `--mcp-allow-origin <ORIGIN>` | A browser origin allowed to call `/mcp` (repeatable). Agents send none. |

Examples:

```sh
teitunnel serve  # tunnels + web dashboard, API and /mcp
teitunnel serve --set-password
```

See [Servers and containers](/docs/guides/servers/).

### route add

Route a hostname to a service on this machine, e.g. `app.teispace.com 3000`.

```sh
teitunnel route add [OPTIONS] <HOSTNAME> <ORIGIN>
```

| Argument | Description |
|---|---|
| `<HOSTNAME>` | Public hostname on one of the account's domains. |
| `<ORIGIN>` | Where traffic goes: a port (`3000`), `host:port`, or a URL. |

| Option | Description |
|---|---|
| `--path <PATH>` | Only requests whose path matches this regex, e.g. `^/api`. |
| `--allow <EMAIL\|@DOMAIN>` | Require a login: an email address, or `@domain` for anyone at that domain. Repeat for more people. Needs Cloudflare Zero Trust (free). |
| `--skip-login <PATH>` | With --allow: a path that skips the login, e.g. `/webhooks`, so webhook senders get through; repeatable. |

**Origin settings**

| Option | Description |
|---|---|
| `--host-header <HOST>` | Host header sent to the service, e.g. for a dev server that checks it. |
| `--no-tls-verify` | Accept any certificate from an HTTPS service (self-signed ones). |
| `--origin-server-name <NAME>` | Hostname expected on the service's TLS certificate. |
| `--match-sni-to-host` | Use the request's hostname as the TLS server name. |
| `--ca-pool <PATH>` | Certificate authority file for the service's certificate. |
| `--http2-origin` | Speak HTTP/2 to an HTTPS service. |
| `--disable-chunked-encoding` | Don't use chunked transfer encoding (some WSGI servers need this). |
| `--connect-timeout <SECONDS>` | Seconds to wait for a connection to the service. |
| `--tls-timeout <SECONDS>` | Seconds to wait for the TLS handshake. |
| `--tcp-keep-alive <SECONDS>` | Seconds between TCP keepalive packets. |
| `--keep-alive-timeout <SECONDS>` | Seconds before an idle keepalive connection closes. |
| `--keep-alive-connections <COUNT>` | Idle keepalive connections kept open. |
| `--no-happy-eyeballs` | Don't fall back between IPv4 and IPv6. |
| `--proxy-type <TYPE>` | `socks` to use the service as a SOCKS5 proxy (TCP routes). |
| `--strict` | Don't add the route when the exposure check finds a leak in the service; by default it only warns. |
| `-a, --account <ACCOUNT>` | Account name or id. |
| `-y, --yes` | Apply without asking. |
| `--replace` | Also allow what needs a confirmation: replacing or deleting DNS records Teitunnel didn't create, or routing a public range. |
| `--take-over` | Take a hostname someone else holds (their reservation, or another machine's route). |
| `--tunnel <TUNNEL>` | One of this machine's tunnels, by name. Default: the tunnel carrying the route, or the default tunnel for a new one. |

Examples:

```sh
teitunnel route add app.teispace.com 3000  # route a hostname to localhost:3000
teitunnel route add api.teispace.com 8000 --path '^/v1/'
teitunnel route add admin.teispace.com 3000 --allow team@teispace.com --allow @teispace.com
teitunnel route add beta.teispace.com 4000 --tunnel staging
teitunnel route add secure.teispace.com https://localhost:8443 --no-tls-verify
teitunnel route add dev.teispace.com 5173 --host-header localhost
teitunnel route add slow.teispace.com 8000 --connect-timeout 60 --keep-alive-timeout 300
```

`--allow` puts a login in front of the route ([Require a login](/docs/guides/require-login/)); `--tunnel` picks one of this machine's tunnels ([Several tunnels](/docs/guides/several-tunnels/)). After adding a route, the command checks it through Cloudflare and exits with status 1 if it doesn't work yet.

The origin settings are cloudflared's `originRequest` settings, the same as the app's (leave them out for cloudflared's defaults):

| Flag | Setting |
|---|---|
| `--host-header` | `httpHostHeader` |
| `--no-tls-verify` | `noTLSVerify` |
| `--origin-server-name` | `originServerName` |
| `--match-sni-to-host` | `matchSNItoHost` |
| `--ca-pool` | `caPool` |
| `--http2-origin` | `http2Origin` |
| `--disable-chunked-encoding` | `disableChunkedEncoding` |
| `--connect-timeout` | `connectTimeout` |
| `--tls-timeout` | `tlsTimeout` |
| `--tcp-keep-alive` | `tcpKeepAlive` |
| `--keep-alive-timeout` | `keepAliveTimeout` |
| `--keep-alive-connections` | `keepAliveConnections` |
| `--no-happy-eyeballs` | `noHappyEyeballs` |
| `--proxy-type` | `proxyType` |

## share

Share a local service, or a folder of files, at a temporary public URL until you press Ctrl-C.

```sh
teitunnel share [OPTIONS] <ORIGIN>
```

| Argument | Description |
|---|---|
| `<ORIGIN>` | What to share: a port (`3000`), `host:port`, a URL, or a folder (`./dist`). |

| Option | Description |
|---|---|
| `--for <DURATION>` | Stop by itself after this long, e.g. `30m`, `2h`, `90s`. |
| `--no-qr` | Don't print a QR code. |
| `--on [HOSTNAME]` | Share at this hostname on one of your domains instead of a random trycloudflare.com address (removed again when the command ends). `{project}`, `{branch}` and `{user}` are filled in from this folder, e.g. `--on {branch}.dev.teispace.com`; `--on` alone uses the name last used here. |
| `--listing` | With a folder: list the files of folders that have no index.html (the default when the folder itself has none). |
| `--no-listing` | With a folder: never list files, even when it has no index.html. |
| `--spa` | With a folder: a single-page app (unknown paths get /index.html). |
| `--schedule <DAYS HH:MM-HH:MM>` | With --on: on only during these hours, paused otherwise, e.g. `"mon-fri 09:00-18:00"`. |
| `--tz <ZONE>` | With --schedule: its time zone, e.g. `Europe/Berlin` (default: this computer's). |
| `-a, --account <ACCOUNT>` | With --on: the account, when several are connected. |
| `--allow <EMAIL\|@DOMAIN>` | With --on: require a login (an email address, or `@domain`); repeatable. |
| `--host-header <HOST>` | Send this Host header to the service, e.g. `localhost:5173` for a dev server that only answers its own address. By default Vite, webpack and Angular dev servers get their own address. |
| `--no-host-header` | Pass the visitor's Host header through unchanged, even to a dev server. |
| `--app` | Share through the running app (it keeps the share after this command ends); fails if the app isn't running. This is the default when the app runs. |
| `--here` | Share from this terminal, for as long as the command runs, even when the app is running. |
| `--json` | Print `{"url": …, "hostname": …}` on stdout once it's live (for scripts and CI). |
| `--strict` | Don't share when the exposure check finds a leak (a .env file, the git folder, debug pages…); by default it only warns. |
| `--no-inspect` | Don't send requests through Teitunnel's inspector (it records them for `teitunnel traffic`, masking credentials). |
| `-q, --quiet` | Don't print a line for each request. |
| `--idle <DURATION>` | Stop after this long without a request, e.g. `30m`. |
| `--watch <PATH>` | Say so when a request hits this path, e.g. `/webhooks/*` (repeatable). |
| `--comments` | Let visitors pin comments on its pages (read and answer them with `teitunnel comments` or in the app). |
| `--mcp` | Share a local MCP server for remote AI clients: checks it answers MCP, keeps streams alive and requires a bearer token (needs --on: Quick Tunnels don't carry event streams). Prints configurations for Claude Code, Cursor and VS Code. |
| `--mcp-path <PATH>` | With --mcp: the server's endpoint path (default: /mcp, then /sse and /). |
| `--ai` | Share a local AI server (Ollama, LM Studio, vLLM) behind a bearer token, for OpenAI-compatible clients. |
| `--new-token` | With --mcp or --ai on your domain: make a new token instead of the saved one. |

Examples:

```sh
teitunnel share 3000                                 # a temporary public URL (in the app when it runs)
teitunnel share 3000 --here --for 30m                # in this terminal, until Ctrl-C or 30 minutes
teitunnel share 3000 --on demo.teispace.com          # the same, on your own domain
teitunnel share 3000 --on {branch}.dev.teispace.com  # named after the git branch
teitunnel share 3000 --on                            # the name used in this folder last time
teitunnel share ./dist                               # share a folder of files
teitunnel share ./dist --on docs.teispace.com --spa
teitunnel share 3000 --no-inspect                    # skip the inspector (on by default)
teitunnel share 8000 --mcp --on mcp.teispace.com     # an MCP server for remote AI clients
teitunnel share 11434 --ai                           # a local AI server behind a bearer token
```

See [Sharing](/docs/guides/sharing/), [Dev servers](/docs/tutorials/dev-servers/) for `--host-header`, the [inspector](/docs/guides/inspector/) and the [exposure check](/docs/guides/exposure-check/).

## protect

Protect a hostname at Cloudflare's edge: challenge or block bots and AI crawlers, rate limit visitors, set or remove headers. Without options, shows what it has now.

```sh
teitunnel protect [OPTIONS] <HOSTNAME>
```

| Argument | Description |
|---|---|
| `<HOSTNAME>` | The hostname, e.g. `app.teispace.com` (a route, or a share on your domain). |

| Option | Description |
|---|---|
| `--bots <BOTS>` | Automated clients (scripts, headless browsers; verified bots like search engines are let through). Values: `off`: Nothing; `challenge`: A managed challenge; `block`: Refused. |
| `--block-ai` | Block AI crawlers (Cloudflare's verified "AI Crawler" bots). |
| `--allow-ai` | Stop blocking AI crawlers. |
| `--rate-limit <N/PERIOD[:ACTION]>` | Requests per period per visitor, then block or challenge: `30/1m`, `100/10s:challenge` (Pro plans and up; periods 10s, 1m, 2m, 5m, 10m, 1h). |
| `--no-rate-limit` | Remove the rate limit. |
| `--set-request-header <NAME:VALUE>` | Set a header on requests before they reach your service: `Name:value`. Repeatable. |
| `--remove-request-header <NAME>` | Remove a header from requests. Repeatable. |
| `--set-response-header <NAME:VALUE>` | Set a header on responses: `Name:value`, e.g. `X-Robots-Tag:noindex`. Repeatable. |
| `--add-response-header <NAME:VALUE>` | Add a header to responses (keeps existing values): `Name:value`. Repeatable. |
| `--remove-response-header <NAME>` | Remove a header from responses. Repeatable. |
| `--clear-headers` | Start from no header rules (then apply the header options given). |
| `--bypass-cache` | Stop Cloudflare caching responses, so a dev server's changes show at once (needs the Cache Rules permission). |
| `--no-bypass-cache` | Let Cloudflare cache responses again. |
| `--off` | Remove every rule Teitunnel added for the hostname. |
| `-a, --account <ACCOUNT>` | Account name or id. |
| `-y, --yes` | Apply without asking. |
| `--json` | Print JSON. |

Examples:


## completions

Print a shell completion script, e.g. `teitunnel completions zsh`. It completes commands and flags, and your hostnames, tunnels, domains, shares and accounts from this machine's records (no network).

```sh
teitunnel completions [OPTIONS] <SHELL>
```

| Argument | Description |
|---|---|
| `<SHELL>` | The shell. Values: `bash`, `zsh`, `fish`, `powershell`, `elvish`. |

| Option | Description |
|---|---|
| `--static` | Commands and flags only, in a script that never runs `teitunnel`. |

Examples:

```sh
teitunnel completions zsh > _teitunnel  # or save it as _teitunnel on your fpath
```

To load them in every new shell:

```sh
source <(teitunnel completions zsh)                  # zsh, in ~/.zshrc
eval "$(teitunnel completions bash)"                 # bash, in ~/.bashrc
teitunnel completions fish > ~/.config/fish/completions/teitunnel.fish
teitunnel completions powershell | Out-String | Invoke-Expression  # in $PROFILE
```

The script asks `teitunnel` for suggestions on every Tab, from this machine's records without going online. `--static` prints a script with only commands and flags that never runs `teitunnel`; Elvish gets that one.
