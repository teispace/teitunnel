`teitunnel` works with the accounts you connected in the app. Every change goes
through the same preview as the app: you see the plan before anything changes.

## Install it

The app puts the `teitunnel` command on your PATH:

- **Windows:** the installer does it (a copy in your user's `WindowsApps` folder, which is
  already on the PATH), and uninstalling removes it.
- **Linux:** the `.deb` and `.rpm` install `/usr/bin/teitunnel`. With the AppImage,
  Teitunnel offers once, after setup, to put it in `~/.local/bin`.
- **macOS:** Teitunnel offers once, after setup, to link it into Homebrew's `bin` (or
  `/usr/local/bin`; if it can't write there, it shows the one `sudo ln -s …` command to
  run). Installed with Homebrew (`brew install --cask teispace/tap/teitunnel`), it's linked
  for you.

You can add or remove it any time in **Settings ▸ General ▸ Command line**. It updates with
the app. For servers without the app, download it on its own from the
[download page](/download/#cli).

## Commands

```sh
teitunnel routes                         # this machine's routes and their status
teitunnel route add app.example.com 3000 # route a hostname to localhost:3000
teitunnel route add api.example.com 8000 --path '^/v1/'
teitunnel route add admin.example.com 3000 --allow me@example.com --allow @example.com
teitunnel route remove app.example.com
teitunnel route balance app.example.com  # load balance across machines (paid add-on)
teitunnel network add 192.168.1.0/24     # let WARP users reach a range
teitunnel networks                       # the ranges this machine shares
teitunnel network remove 192.168.1.0/24
teitunnel export terraform > teitunnel.tf
teitunnel tunnels                        # this machine's tunnels
teitunnel tunnel create staging          # another tunnel for this machine
teitunnel route add beta.example.com 4000 --tunnel staging
teitunnel tunnel delete staging
teitunnel accounts
teitunnel status                        # is the app running, and what does it serve?
teitunnel top                           # a live dashboard (q quits)
teitunnel share 3000                    # a temporary public URL (in the app when it runs)
teitunnel share 3000 --here --for 30m   # in this terminal, until Ctrl-C or 30 minutes
teitunnel share 3000 --on demo.example.com  # the same, on your own domain
teitunnel shares                        # every share: the app's, terminals', your domains'
teitunnel shares --stop demo.example.com
teitunnel analytics                     # traffic of every route, from Cloudflare's edge
teitunnel analytics app.example.com --range week
teitunnel uptime                        # uptime of this machine's routes
teitunnel doctor                        # check for problems; exits 1 on an error
teitunnel doctor --fix                  # apply the safe fixes
teitunnel setup                         # store an API token in the keychain
teitunnel up                            # run this machine's tunnels (servers, Docker)
teitunnel always-on on                  # as a service (a system unit as root)
teitunnel routes --check                # exit 1 unless every route is live
teitunnel serve                         # tunnels + web dashboard, API and /mcp
teitunnel api-key create deploy         # a key for the API (shown once)
teitunnel snapshot publish ./dist --on preview.example.com  # a copy online while you sleep
teitunnel snapshot publish . --build     # build the project, then publish its output
teitunnel snapshot ls                    # Snapshots, their addresses and versions
teitunnel snapshot rollback preview.example.com
teitunnel mcp install cursor            # connect an AI tool (see AI agents)
teitunnel mcp status                    # which AI tools are connected
teitunnel mcp                           # the MCP server itself (clients start it)
```

The MCP commands are described in [AI agents](/docs/guides/ai-agents/).

| Option | Meaning |
|---|---|
| `-a, --account <name or id>` | Which account, when several are connected. |
| `-y, --yes` | Apply without asking (needed when there's no terminal to ask on, e.g. in scripts). |
| `--allow <email or @domain>` | `route add`: require a login; repeat for more people ([Require a login](/docs/guides/require-login)). |
| `--replace` | Also allow what needs a confirmation: replacing or deleting DNS records Teitunnel didn't create, or sharing a public range ([Private networks](/docs/guides/private-networks)). |
| `--tunnel <name>` | Which of this machine's tunnels a change or export is about ([Several tunnels](/docs/guides/several-tunnels)). Default: the tunnel carrying the route, or the default tunnel. |
| `--json` | Machine-readable output for `accounts`, `routes`, `shares`, `status`, `tunnels`, `doctor`, `analytics` and `uptime`. |
| `--app` | `share`, `shares`, `routes`, `top`: go through the running app, and fail if it isn't running. |
| `--here` | `share`, `top`: don't use the app even when it runs (`share` then lasts as long as the command). |
| `--range <hour\|day\|week\|month>` | `analytics`: how far back (default `day`); `--path` narrows it to a route's path ([Analytics](/docs/guides/analytics)). |
| `--for <duration>` | `share`: stop by itself after `90s`, `30m` or `2h` (a bare number is minutes). |
| `--no-qr` | `share`: don't print a QR code. |
| `--host-header <host>` | `share`: send this Host header to the service, e.g. `localhost:5173` ([dev servers](/docs/tutorials/dev-servers)). By default Vite, webpack and Angular dev servers get their own address. |
| `--no-host-header` | `share`: pass the visitor's Host header through unchanged, even to a dev server. |
| `--fix` | `doctor`: apply the fixes that only touch what Teitunnel created, each through a plan. |
| `--build`, `--crawl <url>`, `--password`, `--expires 7d` | `snapshot publish`: build the project first, capture a running site, ask visitors for a password, delete it later ([Snapshots](/docs/guides/snapshots)). |

Routes are served by the app while it's open, all the time with
[Always-on](/docs/concepts/run-modes) (`always-on on` from the CLI), or by
`teitunnel up` on a server or in a container. Without the app, give the API token in
`CLOUDFLARE_API_TOKEN` or `CLOUDFLARE_API_TOKEN_FILE`; it's never stored
([Servers and containers](/docs/guides/servers)). After adding a
route, the CLI checks it through Cloudflare and exits with status 1 if it doesn't work yet.

## With the app running

When the Teitunnel app is running, `teitunnel` uses it through its
[control connection](/docs/guides/integrations/):

- `teitunnel share 3000` asks the app to share the port. The share shows up in the app's
  Quick Share and keeps running after the command ends; stop it there or with
  `teitunnel shares --stop <url>`. The first time, the app asks you to allow the command
  line (choose **Always Allow** to not be asked again). `--for` still works, and `--here`
  shares from the terminal instead.
- `teitunnel shares` lists the app's shares too, and `--stop` stops any of them.
- `teitunnel routes` shows the status the app's connectors report.
- `teitunnel status` says whether the app runs, its tunnels and what it shares.

Without the app every command works on its own, as below.

## Sharing from the terminal

Without the app (or with `--here`), `share` runs a Quick Share for exactly as long as the
command. Ctrl-C, closing the terminal or `--for` stops it. The URL is the only line on standard output, so
`URL=$(teitunnel share 3000 | head -1)` works in scripts. `share` doesn't need an
account, only cloudflared (the app's copy, or one on your system). Once the URL is live,
`share` checks it through Cloudflare and, if your dev server refuses the address or the
service streams events a Quick Share can't carry, says what to do on standard error; it keeps
sharing either way.

`doctor` runs the app's checks and hides the issues you ignored there.

## Origin settings

`route add` takes the same origin settings as the app (leave them out for cloudflared's
defaults):

```sh
teitunnel route add secure.example.com https://localhost:8443 --no-tls-verify
teitunnel route add app.example.com 5173 --host-header localhost
teitunnel route add slow.example.com 8000 --connect-timeout 60 --keep-alive-timeout 300
```

| Flag | Setting |
|---|---|
| `--host-header HOST` | `httpHostHeader` |
| `--no-tls-verify` | `noTLSVerify` |
| `--origin-server-name NAME` | `originServerName` |
| `--match-sni-to-host` | `matchSNItoHost` |
| `--ca-pool PATH` | `caPool` |
| `--http2-origin` | `http2Origin` |
| `--disable-chunked-encoding` | `disableChunkedEncoding` |
| `--connect-timeout`, `--tls-timeout`, `--tcp-keep-alive`, `--keep-alive-timeout` SECONDS | the timeouts |
| `--keep-alive-connections COUNT` | `keepAliveConnections` |
| `--no-happy-eyeballs` | `noHappyEyeballs` |
| `--proxy-type socks` | `proxyType` |

## teitunnel top

`teitunnel top` is a live view of your shares (address, service, age, requests per
second), routes (a status dot, where they go, uptime over 24 hours), traffic, and the
requests of a share the app inspects. It reads from the app when it runs; otherwise from
this machine's records (then you can see and stop terminals' shares, but not start new
ones).

| Key | Does |
|---|---|
| `q`, `Esc` | quit (`Esc` first clears a filter) |
| `Tab` | next pane |
| `↑` `↓`, `j` `k` | select |
| `s` | share a port (through the app) |
| `x` `x` | stop the selected share (press twice) |
| `c` | copy the selected URL (through the terminal, so it works over SSH too) |
| `/` | filter everything by text |
| `?` | the keys |

It follows the terminal's size and uses no colour when `NO_COLOR` is set.

## Shell completions

Completions include your own names: hostnames of your routes, tunnels, domains, shares and
accounts, read from this machine's records without going online.

```sh
source <(teitunnel completions zsh)                  # zsh, in ~/.zshrc
eval "$(teitunnel completions bash)"                 # bash, in ~/.bashrc
teitunnel completions fish > ~/.config/fish/completions/teitunnel.fish
teitunnel completions powershell | Out-String | Invoke-Expression  # in $PROFILE
```

For zsh you can also save the script as `_teitunnel` in a folder on your `fpath`. The
script asks `teitunnel` for suggestions on every Tab. `--static` prints a script with only
commands and flags that never runs `teitunnel`; Elvish gets that one.

The first time it reads your Cloudflare token, macOS asks whether `teitunnel` may use
the keychain item Teitunnel created. Choose **Always Allow** to not be asked again.
